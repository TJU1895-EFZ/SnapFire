# SnapFire

SnapFire（SnapFire MR 实景枪战）是一款面向真实场地的**混合现实（MR）真人枪战应用**。玩家各自捧着 Windows 笔记本，把摄像头当作枪口、屏幕当作瞄准镜，在真实房间里移动、瞄准、射击。

> **当前发布：v1.0.0。** 首个可玩模式是「团战 → 巷战（室内）」。**团战不是产品的全部**：SnapFire 的目标是让真人枪战在普通笔记本上落地，后续会扩展野战（室外）和其他真人枪战玩法。v1.0.0 已完成真实双机/真人现场验收（2026-10-24 LAN 房间 2 场实战，4~5 人参与，红线 0 错误归属）。

---

## 1. 项目解决什么问题

传统真人 CS / 激光枪通常需要专用枪械、感应背心、场地设备和工作人员；Airsoft 则有安全、场地和装备成本。SnapFire 希望用玩家已有的 Windows 笔记本和摄像头，在室内空间完成一场可计分、可复活的真人枪战：

- 不需要头显、枪械外设、感应背心或手机；
- 不需要互联网和云服务，同一局域网即可；
- 笔记本摄像头画面作为取景器，屏幕叠加 AR 手臂/枪和准心；
- 用本地离线的人脸 + 衣着识别判断"准心拍到的是谁"；
- 血量、比分、复活、比赛结果自动同步，并保存在本机。

它不是 VR 游戏：玩家在真实空间里移动，用真实动作瞄准真人；也不是传统 FPS：屏幕里是真实摄像头画面，不是虚拟地图。

**当前 V1 只实现团战（巷战/室内）一个模式**；野战/室外和其他玩法还在后续规划中。

## 2. 主要功能

### 2.1 真人枪战基础能力

- 摄像头取景 + AR 手臂/枪 + 准心（当前为风格化占位 3D 模型）
- 赛前人脸 + 衣着建档；人脸不可用时仍可用衣着识别
- 准心附近目标识别：锁定昵称/队伍；识别不确定时显示"目标未识别"，按未命中处理
- 命中扣血、误伤队友不扣血、阵亡/复活
- 本地数据、自动备份、导出/导入

### 2.2 当前已开发模式：团战 · 巷战（室内）

- 1V1 到 3V3；一房最多 6 人，红蓝各最多 3 人，玩家自选队伍
- 交火距离设计目标最远 10 米
- 房主创建房间，显示 `IP:端口` + 4 位房间号；其他玩家局域网加入
- 赛前建档、选队、准备、房主开始
- 默认 5 分钟 / 10 杀；房主可调 3 到 10 分钟 / 10 到 30 杀
- 时间到或某队先到击杀上限，任一条件结束
- 统一伤害 25 血/枪，满血 100，4 枪击倒；V1 不做身体部位差异伤害
- 阵亡 5 秒后满血复活，复活后 2 秒无敌
- 结算页、个人数据、历史战绩、返回大厅

> 再次说明：**团战是当前先开发出来的模式，不是 SnapFire 产品全貌。** 产品定位是"真实场地里的 MR 真人枪战"；野战和其他玩法暂未开放。

### 2.3 当前不做 / 未开放

- 野战（室外）模式：首页保留入口，显示"敬请期待"
- 身体部位差异伤害
- 弹匣/换弹/多把武器（当前一把枪、无限子弹 + 射速冷却）
- 登录、云数据库、手机端、公网联机
- 排行榜、商城、皮肤、语音、观战、回放
- 自动匹配/排位
- 断线重连、复杂反作弊
- 正式安装包/自动更新（v1.0.0 以便携 zip 分发）

## 3. 安装方法

### 3.1 普通玩家：下载 Release 便携版（推荐）

v1.0.0 以便携 zip 发布：

1. 打开本项目的 **GitHub Releases** 页面：https://github.com/TJU1895-EFZ/SnapFire/releases
2. 下载 `SnapFire-1.0.0-win-x64.zip` 和 `SHA256SUMS.txt`。
3. 解压到任意可写目录（例如 `D:\Games\SnapFire`；不要解压到需要管理员权限的目录）。
4. 双击 `SnapFire.exe`。

可选校验（与 `SHA256SUMS.txt` 对照）：

```powershell
Get-FileHash .\SnapFire-1.0.0-win-x64.zip -Algorithm SHA256
```

特点：

- 无需 Node.js、无需安装、不写桌面/开始菜单快捷方式；
- Windows 10/11 x64；
- 首次启动会停留约 10 秒加载/预热本地识别模型；
- 数据保存在 `%APPDATA%\SnapFire\data`，删除解压目录不会删除战绩；
- 未签名版本可能触发 Windows SmartScreen：点"更多信息 → 仍要运行"（仅在你信任来源时）。

### 3.2 从源码运行（开发/测试）

环境：

- Windows 10/11 x64
- Node.js 20+（验证过 Node 24）
- npm 10+
- 摄像头；建议 2 台以上电脑在同一局域网

```powershell
cd "你的项目目录"
npm install
```

如果 Electron 二进制下载失败（国内网络）：

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
node node_modules/electron/install.js
```

开发模式：

```powershell
npm run dev
```

生产模式：

```powershell
npm run build
npx electron .
```

项目根目录的 `start-snapfire.cmd` 可双击启动已构建版本（会短暂出现命令窗口；不创建桌面/开始菜单快捷方式）。

### 3.3 多台电脑联机准备

- 每台电脑都需要一份应用：Release zip 解压，或源码 + `npm install`；
- 所有电脑连接同一个 Wi-Fi/热点/局域网；
- 首次开房时 Windows 防火墙提示，请允许"专用网络"；
- 房主显示 `IP:端口` 和 4 位房间号；其他玩家输入这两项加入；
- 如果房主有多个网卡/VPN，界面显示的地址可能不是 Wi-Fi 地址；可用 `ipconfig` 找到正确的 IPv4，再加端口连接。

## 4. 使用方法

### 4.1 创建 / 加入房间

1. 启动 SnapFire，首页点击「巷战（室内）」。
2. 房主：点击「创建房间」，记下 `IP:端口` 和 4 位房间号。
3. 其他玩家：点击「加入房间」，输入房主地址（如 `192.168.1.20:17890`）和房间号。
4. 双方大厅显示玩家数量；一房最多 6 人，红蓝各最多 3 人。

### 4.2 赛前建档

1. 玩家在大厅点击「去建档」。
2. 面对摄像头，点击「采集正面」。
3. 转身背对摄像头，点击「采集背面」；侧身可选。
4. 至少正面 + 背面都采集成功后才能「保存建档」。
5. 没有清晰人脸也可以保存（主要依靠衣着）；建议两人衣着颜色/图案有明显差异。

### 4.3 选队、准备、开始

1. 玩家自行选择红队或蓝队（每队最多 3 人；支持 1V2 等不等人数）。
2. 非房主点击「准备」。
3. 房主根据「开局检查」确认：至少 2 人、双方有队员、所有人已选队、已建档、已准备。
4. 房主设置比赛时长（3~10 分钟）和击杀上限（10~30 杀）。
5. 房主点击「开始比赛」，3 秒倒计时后进入战斗。

### 4.4 战斗操作

| 操作 | 方式 |
| --- | --- |
| 开火 | 空格 / 鼠标左键 |
| 瞄准 | 移动笔记本，让屏幕中心准心对准目标 |
| 离开本局 | Esc（弹出确认） |
| 查看锁定 | 准心旁显示昵称/队伍；未识别显示"目标未识别" |

规则：

- 命中敌人：每枪 25 血，4 枪击倒；
- 命中队友：不扣血，提示误伤无效；
- 识别不到：按未命中处理，不猜测扣血；
- 阵亡：5 秒后满血复活，复活后 2 秒无敌；
- 比赛结束：时间到或某队先到击杀上限，任一条件满足；
- 当前一把枪、无限子弹 + 射速冷却，无换弹。

### 4.5 结算、历史与返回大厅

- 比赛结束显示胜方（红队/蓝队/平局）、比分、个人击杀/死亡/命中率；
- 战绩自动保存到本机；
- 房主可「返回大厅」再开一局；其他玩家等待房主；
- 「离开房间」回到首页。

### 4.6 数据与备份

- 数据目录：`%APPDATA%\SnapFire\data`（设置页显示实际路径）。
- 文件：`profile.json`、`settings.json`、`appearance.json`、`history.json`、`backups/`。
- 自动备份：启动时、每局结束后；保留最近 10 份。
- 设置页支持导出备份、导入备份、清除本地数据；导入前会自动生成恢复前备份。
- 原始建档照片只保存在本机；房间只同步识别特征，不传照片。

## 5. 输入 / 输出示例

> 以下地址、房间号、玩家名均为示例，实际值以界面为准。

### 5.1 输入

| 输入 | 示例 | 说明 |
| --- | --- | --- |
| 房主地址 | `192.168.1.20:17890` | 加入房间时填写 |
| 房间号 | `4821` | 4 位数字 |
| 昵称 | `玩家A` | 本地档案，最多 16 字符 |
| 建档画面 | 正面、背面摄像头画面 | 提取人脸特征 + 衣着特征 |
| 队伍 | 红队 / 蓝队 | 每队最多 3 人 |
| 比赛设置 | 5 分钟 / 10 杀 | 房主可调 3~10 分钟 / 10~30 杀 |
| 开火 | 空格 / 鼠标左键 | 准心对准已建档玩家 |
| 离开 | Esc | 确认后离开本局 |

### 5.2 输出

| 输出 | 示例 |
| --- | --- |
| 房间信息 | `192.168.1.20:17890` / `4821` |
| 锁定提示 | `锁定 · 玩家B` + 蓝队标识 |
| 未识别 | `目标未识别`（本次不扣血） |
| 队友提示 | `队友 · 未造成伤害` |
| 命中反馈 | 玩家B 血量 `100 → 75 → 50 → 25 → 0` |
| 阵亡/复活 | `阵亡，5 秒后复活`；复活后 `2 秒保护` |
| 比分/计时 | `RED 7 : 3 BLUE`，`04:12` |
| 结算 | `红队获胜`；个人击杀/死亡/命中率 |
| 本机文件 | `%APPDATA%\SnapFire\data\history.json` 等 |

### 5.3 示例一局

1. 玩家A 创建房间，界面显示 `192.168.1.20:17890` 和房间号 `4821`。
2. 玩家B 加入，完成正面/背面建档，选择蓝队并点「准备」。
3. 玩家A 选择红队，比赛设置保持 5 分钟 / 10 杀，点击「开始比赛」。
4. 倒计时结束，玩家A 把准心对准玩家B，界面显示 `锁定 · 玩家B` 和蓝队标识。
5. 玩家A 按空格开火；玩家B 屏幕显示受击，血量从 100 降到 75；第 4 次命中后阵亡，5 秒后复活。
6. 时间到或某队先到 10 杀，比赛结束。假设比分 7:3，结算页显示红队获胜；双方本机历史战绩各保存一条。
7. 房主返回大厅，可开下一局。

如果准心附近没有人或无法确认身份，界面显示"目标未识别"，本次开火不扣任何人的血。

## 6. 当前状态、限制与测试

- **版本**：v1.0.0；代码功能完成，自动化测试通过；真实双机/真人现场验收已完成（2026-10-24 LAN 房间 2 场实战，红线 0 错误归属）。
- **识别距离**：设计目标最远 10 米；10 米处人脸通常不可用，主要靠衣着。逆光、暗光、相似服装会降低成功率。
- **不误扣原则**：识别不确定时按未命中处理，不猜测目标。
- **美术**：首页角色为原创 SVG；手臂/枪械为 Three.js 基础几何体占位模型，不是最终美术。
- **玩法**：当前只有团战/巷战；野战、身体部位伤害、换弹、多武器、排行/商城/语音/观战等未开发。
- **网络**：局域网；无登录、无云、无公网联机；无断线重连。
- **数据**：本地 JSON，未加密；请勿在公用电脑保存敏感照片。
- **分发**：v1.0.0 为便携 zip，无安装包/自动更新；未签名可能触发 SmartScreen。
- **场地测试**：设置中可启用逐枪 JSONL 日志（默认关闭，仅本机，不记录图像）；流程见 `field-tests/README.md`。

测试状态：

- `npm run typecheck` 通过；
- `npm test`：6 个测试文件、35 项测试通过；
- `npm run build` 通过；
- `npm run test:smoke`：两个 Electron 实例，假摄像头，完整走通大厅 → 战斗 → 开火 → 结算 → 战绩保存 → 返回大厅；
- 便携 zip 已构建并测试：`release/SnapFire-1.0.0-win-x64.zip`（约 158MB）；打包后的 `SnapFire.exe` 和解压 zip 均通过完整双实例冒烟（Human 模型从 asar 离线加载），并校验场地测试 JSONL 的 `session` / `shot` / `match-end`；

## 8. 常见问题

**Q：加入房间连接失败？**

- 确认在同一局域网；地址是房主 Wi-Fi IPv4 + 端口；防火墙允许专用网络；房间号正确。

**Q：摄像头打不开？**

- Windows 设置 → 隐私和安全性 → 摄像头，允许应用访问；关闭占用摄像头的程序；设置页切换设备。

**Q：一直显示"目标未识别"？**

- 双方完成建档；距离 3~6 米效果最好；衣服差异明显；光线充足；可在设置页把识别质量调到「精准」。

**Q：启动卡在加载页？**

- 首次启动需加载/预热模型；若长时间不结束，检查模型文件或终端错误。

**Q：npm install 后 Electron 起不来？**

- 使用镜像命令重新安装 Electron 二进制；确认 `node_modules/electron/path.txt` 存在。
